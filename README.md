# 黑板

兩個人共用的一塊黑板。你在 iPhone 上畫一筆，對方裝置上同時看到那筆長出來。

- 型態：B（單頁前端 + Firebase Realtime Database）
- 安裝方式：PWA，用瀏覽器開一次後「加入主畫面」，不必上架 App Store
- 費用：Firebase Spark 免費方案，不需綁信用卡，不會產生帳單

---

## 一、檔案

| 檔案 | 作用 |
|---|---|
| `index.html` | 介面骨架 |
| `style.css` | 黑板外觀與 RWD |
| `app.js` | 繪圖、同步、橡皮擦、復原、清除 |
| `firebase-config.js` | 你的 Firebase 設定值（只需要 `databaseURL`） |
| `database.rules.json` | 資料庫安全規則，要貼進 Firebase 主控台 |
| `manifest.webmanifest` | PWA 設定（App 名稱、圖示、全螢幕） |
| `sw.js` | Service Worker，PWA 的必要條件 |
| `icon-192.png` / `icon-512.png` | App 圖示 |

## 二、Firebase 設定（只有一個人要做）

對方不需要申請任何東西，他只要拿到網址和邀請碼。

1. 專案與資料庫已建立：`messages-on-the-blackboa-176e7`，位置 `asia-southeast1`。
2. **貼上安全規則**：Firebase 主控台 → Realtime Database → 「規則」分頁 →
   把 `database.rules.json` 的內容整份覆蓋進去 → 發布。

   > 這一步不做，App 會完全讀不到也寫不進去（因為建立時選了鎖定模式，
   > 預設是 `.read: false, .write: false`）。

3. 不需要「註冊網頁應用程式」，也不需要 `apiKey`。
   `apiKey` 只在使用 Firebase 驗證服務時才需要，本專案不使用。

## 三、部署（兩條路，挑一條）

PWA 必須跑在 **HTTPS** 上才能加入主畫面，所以不能只在本機雙擊開啟。

### 路線 A — Firebase Hosting（要裝 Node.js）

```bash
npm install -g firebase-tools
firebase login
cd blackboard
firebase init hosting     # public 目錄填 .   single-page app 選 N   不要覆寫 index.html
firebase deploy --only hosting
```

部署完會給你一個 `https://你的專案.web.app` 網址。

### 路線 B — GitHub Pages（不用裝任何東西）

1. 到 github.com 建立一個新的 repository（Public）
2. 點 **Add file → Upload files**，把這個資料夾裡的所有檔案拖上去，Commit
3. 進 **Settings → Pages**，Source 選 `Deploy from a branch`，分支選 `main`、資料夾選 `/ (root)`，Save
4. 等一兩分鐘，網址會是 `https://你的帳號.github.io/repo名稱/`

兩條路都提供 HTTPS，PWA 都能正常加入主畫面。

### 本機測試（開發用，不能加入主畫面）

```bash
cd blackboard
python3 -m http.server 8000
```
然後開 `http://localhost:8000`。`localhost` 算安全情境，SHA-256 與 Service Worker 都能運作。

## 四、兩個人怎麼用

1. 你把網址傳給對方，並**另外**告訴他邀請碼（建議 10 個字元以上）
2. 各自用 Safari 開啟網址 → 輸入**完全相同**的邀請碼 → 選自己的粉筆顏色
3. 點下方分享鍵 → 往下滑找到「**加入主畫面**」→ 命名「黑板」→ 加入
4. 之後從主畫面圖示開啟，全螢幕，沒有瀏覽器網址列

**邀請碼的運作方式**：前端把邀請碼做 SHA-256，取前 32 個十六進位字元當資料庫路徑。
原始邀請碼不會離開裝置。外人就算拿到 `databaseURL`，也得猜中那 32 個字元才進得來。

**安全邊界**（已知且接受的限制）：
- 這不是密碼，沒有踢人功能。邀請碼若外流，換一組新的等於開一塊全新黑板
- 知道邀請碼的人可以讀、可以畫、也可以清除黑板
- 邀請碼請勿設成 `1234` 這類短字串

## 五、操作

| 動作 | 說明 |
|---|---|
| 畫圖 | 手指或 Apple Pencil 直接畫，本機立刻顯示，對方約一秒內看到 |
| 筆粗 | 工具列左側三個圓點，細 / 中 / 粗 |
| 橡皮擦 | 點一下切換，碰到的筆畫整筆刪除（**包含對方畫的**） |
| 復原 | 只收回自己最近一筆，可連按，上限 20 筆 |
| 清除整塊 | 垃圾桶鍵**長按兩秒**，兩邊一起清空。放開即取消 |
| 連線狀態 | 右上角圓點，綠＝已連線，灰＝離線（筆畫暫存本機，恢復後自動補送） |

顏色固定不可改，因為顏色就是辨識誰畫的唯一依據。

## 六、技術規格

- 座標存成 0–1000 的整數（畫布寬高的千分比），畫布固定 **9:16** 直式並置中，
  所以不同螢幕尺寸看到的構圖完全一致。
  比例由 `app.js` 的 `ASPECT` 常數決定，改一行就能換（例如 `3 / 4`）。
  已經畫過的內容會依新比例被拉伸，建議要改就趁黑板是空的時候
- 一筆畫邊畫邊推送，節流 100 ms；單筆超過 400 點自動切段
- 黑板筆畫上限 2000 筆，超過自動丟棄最舊的
- 離線寫入由 Firebase SDK 自己的佇列處理，恢復連線後自動補送
- 資料結構：
  ```
  /boards/{32字元房間路徑}/strokes/{pushId}
      u  作者代號（localStorage 隨機 8 碼）
      c  顏色 "p" 粉紅 / "b" 淺藍
      w  筆粗 1 / 2 / 3
      p  座標字串 "x,y,x,y,..."（千分比整數）
      d  是否畫完 0 / 1
  ```

| 項目 | Spark 免費額度 | 兩人實際用量 |
|---|---|---|

## 七、驗收測試清單

兩台裝置都開好之後，依序測這七項：

| # | 測試 | 預期結果 |
|---|---|---|
| 1 | A 畫一筆 | B 在 1 秒內看到，**位置與形狀一致** |
| 2 | 兩台同時畫 | 兩筆都保留，不互相覆蓋或消失 |
| 3 | A 用橡皮擦擦掉 B 的筆畫 | B 裝置上該筆也消失 |
| 4 | A 按復原 | 只收回 A 自己最近一筆，B 的不動 |
| 5 | B 開飛航模式畫三筆，再關掉 | 三筆補送成功，A 看得到 |
| 6 | 兩台橫豎螢幕各轉一次 | 構圖不變形、不位移（畫布恆為 9:16） |
| 7 | 兩台關掉重開 | 所有筆畫完整還在 |

第 1 項是最關鍵的一項，它在抓座標正規化的錯誤。

## 八、疑難排解

| 症狀 | 原因 |
|---|---|
| 畫得出來但對方看不到 | 兩人邀請碼不一樣（大小寫會自動統一，但空白與錯字不會） |
| 完全畫不出來、主控台出現 `PERMISSION_DENIED` | 安全規則還沒貼上去發布 |
| 右上角圓點一直是灰的 | `firebase-config.js` 的 `databaseURL` 打錯 |
| 分享選單找不到「加入主畫面」 | 要往下滑；或該瀏覽器未支援，改用 Safari |
| 圖示是網頁截圖不是 App 圖示 | `icon-192.png` 沒跟著一起上傳 |

要換一塊全新的黑板：兩人都清掉瀏覽器資料重新輸入新邀請碼，或直接在程式裡改。
舊黑板的筆畫會留在資料庫的舊路徑，可以到 Firebase 主控台手動刪除。
